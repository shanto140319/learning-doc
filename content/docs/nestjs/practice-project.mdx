Rebuild your [Node.js practice project](/docs/node-http/practice-project) in NestJS. Same features, same behaviour, but each concern now lives in the right building block. When you finish, compare the two codebases side by side: that comparison is a great blog post and interview story.

Time: one Friday block (about 4 hours) plus one or two weekday sessions. Data stays in memory; Prisma and PostgreSQL come next.

## Requirements

### Endpoints

| Endpoint | Who | Notes |
| --- | --- | --- |
| `GET /v1/services` | Public | List |
| `POST /v1/services` | owner, admin | `CreateServiceDto`, 201 + `Location` |
| `PATCH /v1/services/:id` | owner, admin | `UpdateServiceDto` (`PartialType`) |
| `DELETE /v1/services/:id` | owner | 204 |
| `GET /v1/bookings` | Any logged-in user | `ListBookingsQuery`: cursor pagination, filters, sort allow-list. Scoped to the user's business |
| `POST /v1/bookings` | Public (customers book) | `CreateBookingDto`, `Idempotency-Key` required, 409 `slot-taken` |
| `GET /v1/bookings/:id` | Any logged-in user | 404 for other businesses' bookings |
| `POST /v1/bookings/:id/cancel` | Any logged-in user | 409 `already-cancelled` |
| `GET /v1/bookings/export` | owner, admin | CSV stream (`StreamableFile` or `@Res()` + `pipeline`) |
| `GET /v1/audit-log` | owner | From Lesson 8 |
| `GET /health/live`, `GET /health/ready` | Public | Terminus |
| `GET /docs` | Public (dev) | Swagger |

### Quality checklist

- [ ] Feature modules: `services`, `bookings`, `audit`, `health`, plus `common/` and `config/`
- [ ] Controller → service → repository in each feature; controllers have no business logic
- [ ] `AuthGuard` and `RolesGuard` registered with `APP_GUARD`; `@Public()` and `@Auth(...)` decorators
- [ ] Global `ValidationPipe` (`whitelist`, `forbidNonWhitelisted`, `transform`) with field errors
- [ ] One global `ProblemDetailsFilter`: **every** error has the same shape and `application/problem+json`
- [ ] Responses mapped with `toXResponse()` functions; no internal fields
- [ ] `@CurrentUser('businessId')` passed into services; no cross-tenant access
- [ ] Idempotency for `POST /v1/bookings` as an **interceptor** (see the scaffold below)
- [ ] `ConfigModule` with Zod validation, `.env.example` committed
- [ ] Swagger with the CLI plugin, success and error responses documented
- [ ] nestjs-pino with request IDs and redaction; no `console.log`
- [ ] `enableShutdownHooks()`, Helmet, CORS from config, URI versioning
- [ ] Unit tests: `BookingsService` (create, cancel), `RolesGuard`, the idempotency interceptor
- [ ] One e2e test with Supertest (the `test/app.e2e-spec.ts` file `nest new` created): create a booking, replay with the same key, get the same ID
- [ ] `strict` TypeScript, no `any`

## Test checklist

Run the same 11 checks as the [Node practice project](/docs/node-http/practice-project#test-checklist), plus:

1. No token on `POST /v1/services` → 401. `token-staff` → 403. `token-owner` → 201. All in problem+json.
2. `token-owner` of `biz_1` asks for a `biz_2` booking → 404.
3. `GET /v1/bookings?limit=abc` → field error for `limit`.
4. Body with an extra `"status": "cancelled"` field → rejected.
5. Every response has `X-Request-Id`, and the same ID is in the log line.
6. Stop the fake database (`FAKE_DB_DOWN=true`) → `/health/ready` 503, `/health/live` 200.
7. Swagger: you can authorise and run every endpoint from `/docs`.
8. `npm test` and `npm run test:e2e` both pass.
