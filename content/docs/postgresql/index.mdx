PostgreSQL ("Postgres") is the default database for new TypeScript backends, and it's in almost every remote full-stack job ad you're targeting. Interviewers expect more than CRUD: they ask how you'd model data, why a query is slow, and what happens when two requests change the same row at the same time.

All examples build the **booking platform** (Project 1). By the end, your NestJS booking API stores everything in Postgres, and **the database itself makes double bookings impossible**, even under heavy concurrent traffic.

## Setup

You need Docker Desktop. (If you can't use Docker, install PostgreSQL 18 for Windows from postgresql.org; everything else is the same.)

Create a practice folder, for example `pg-practice`, next to your `booking-api` project, and add `docker-compose.yml`:

```yaml
services:
  db:
    image: postgres:18
    container_name: booking-pg
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
      POSTGRES_DB: booking
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql   # PostgreSQL 18 images use this path (not .../data)
    command: ["postgres", "-c", "shared_preload_libraries=pg_stat_statements"]

volumes:
  pgdata:
```

```powershell
docker compose up -d
docker exec -it booking-pg psql -U postgres -d booking
```

You should see the `booking=#` prompt. Type `select version();` and check it says PostgreSQL 18. Type `\q` to quit.

A GUI is useful too: **DBeaver** (free), **TablePlus**, or the **PostgreSQL extension for VS Code**. Connection: host `localhost`, port `5432`, user `postgres`, password `postgres`, database `booking`. Still learn `psql`: in interviews and on servers, it's what you'll have.

## How each lesson works

Same as before: type the examples yourself (don't copy and paste), do the exercises without help, send them to Claude for a scored review, then check the [Solutions](/docs/postgresql/solutions). Write your mistakes in each page's notes box and practise the interview answers out loud.

Keep every SQL file you write in `pg-practice/sql/` (`01-basics.sql`, `02-schema.sql`, …). You'll reuse them, and they become your personal reference.
