Until now, your booking API used a fake login: the token `token-owner` was just a user ID. In this section you replace it with **real authentication** (who are you?) and **real authorisation** (what are you allowed to do?), and you learn the attacks that break both.

Security questions appear in almost every full-stack interview: "Where do you store the JWT?", "How do refresh tokens work?", "What is CSRF and how do you stop it?", "How do you stop one customer seeing another customer's data?". After this section, you can answer each one with code you wrote.

All examples build on the **booking API** from the [PostgreSQL practice project](/docs/postgresql/practice-project) (NestJS + Prisma 7 + PostgreSQL 18).

All of them are covered. SQL injection and row-level security were already covered in [PostgreSQL Lesson 10](/docs/postgresql/lesson-10-multi-tenancy-and-scaling), so here they get only a short reminder.

## Setup

You need the booking API from the PostgreSQL project, plus a local email inbox. **Mailpit** catches every email your app sends and shows it in a web page, so you never send real emails while learning. Add it to the `docker-compose.yml` that runs Postgres:

```yaml
  mail:
    image: axllent/mailpit
    container_name: booking-mail
    ports:
      - "1025:1025"   # SMTP: your app sends here
      - "8025:8025"   # web UI: open http://localhost:8025
```

Install the packages you'll use in this section:

```powershell
npm i argon2 @nestjs/jwt cookie-parser @nestjs/throttler helmet openid-client nodemailer
npm i -D @types/cookie-parser @types/nodemailer
```

Add these to your Zod `EnvSchema` from [NestJS Lesson 6](/docs/nestjs/lesson-6-config-and-decorators) (and to `.env.example` without real values):

```typescript
APP_URL: z.string().url(),                   // the frontend, e.g. http://localhost:3001
JWT_SECRET: z.string().min(32),              // already there
COOKIE_SECRET: z.string().min(32),           // signs short-lived cookies (Lesson 5)
SMTP_URL: z.string().url(),                  // smtp://localhost:1025 for Mailpit
GOOGLE_CLIENT_ID: z.string().min(1),         // Lesson 5
GOOGLE_CLIENT_SECRET: z.string().min(1),
GOOGLE_REDIRECT_URI: z.string().url(),
ENCRYPTION_KEY: z.string().length(44),       // 32 random bytes in base64 (Lesson 9)
```

Generate random secrets like this (never type them yourself):

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"
```

## How each lesson works

Same as before: type the examples yourself, do the exercises without help, send them to Claude for a scored review, then check the [Solutions](/docs/auth-security/solutions). Write your mistakes in each page's notes box and practise the interview answers out loud.

Security has one extra rule: **attack your own code**. Most exercises end with "now try to break it". Write down what you tried, even when it failed. That list becomes the security section of your README, and it's great interview material.
