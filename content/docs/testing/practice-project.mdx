Give the booking platform a test suite that you'd be happy to show in an interview. When you're done, anyone can clone the repo, run `npm run test:all` with only Docker running, and see every rule of the platform checked in a few minutes. And a green CI badge on GitHub proves it runs on every change.

This is the project where "I write tests" becomes "here are my tests, and here's a bug they caught".

Time: one Friday block (about 4 hours) plus three or four weekday sessions.

## Requirements

### Test infrastructure

- [ ] `npm test`: unit tests only, no Docker, under 10 seconds
- [ ] `npm run test:int`: integration and API tests with Testcontainers (`postgres:18-alpine`), migrations applied once, one database per Jest worker
- [ ] `test/setup/env.ts` sets every env var with fake values and `TZ=UTC`; no `.env` file needed to run tests
- [ ] `configureApp()` shared by `main.ts` and `createTestApp()`
- [ ] Builders (`anActor`, `aBooking`) for unit tests and factories (`f.salon()`, `f.member()`, `f.userWithPassword()`) for database tests
- [ ] `Clock` provider used by every rule that depends on time
- [ ] MSW for outside HTTP calls, with only localhost allowed through
- [ ] `clearMocks` and `restoreMocks` on in both Jest configs
- [ ] ESLint's Jest plugin with `no-focused-tests` and `no-disabled-tests` (warn)

## Scaffold: the bug hunt

A suite is only good if it **catches bugs**. Prove it. On a new branch `bug-hunt`, make each change below **one at a time**, run the tests, write down which test failed, and undo the change:

| # | Break this | Which test should catch it? |
| --- | --- | --- |
| 1 | `overlaps`: `<` becomes `<=` | |
| 2 | Drop the `bookings_no_overlap` constraint in a new migration | |
| 3 | `BookingsRepository.findOne`: remove `businessId` from the `where` | |
| 4 | Remove `@Roles(['owner', 'admin'])` from `DELETE /v1/services/:id` | |
| 5 | `MembershipGuard`: skip the membership lookup and trust `X-Business-Id` | |
| 6 | Refresh: remove the reuse check (always rotate) | |
| 7 | Login: return "User not found" for unknown emails | |
| 8 | Password reset links: 30 minutes becomes 30 hours | |
| 9 | The booking response includes `customer.phone` | |
| 10 | Map the exclusion constraint error to 500 instead of 409 | |
| 11 | `OriginGuard`: allow any `Origin` | |
| 12 | `BookingForm`: remove `if (sending) return` and the `disabled` attribute | |

Your suite must catch **at least 11 of 12**. For each one it misses, write the missing test, then run the hunt again. Put the final table in `TESTING.md`: it's excellent interview material ("I broke my own code twelve ways to check my tests").

## TESTING.md

A short document in the API repo (1–2 pages):

1. **How to run:** the commands, what each needs (Docker? Mailpit?), how long each takes on your machine.
2. **Strategy:** which kinds of tests you write for what, and why most tests use a real Postgres. A small diagram or table of the layers.
3. **Conventions:** file names (`.spec.ts`, `.int-spec.ts`, `.e2e-spec.ts`), builders vs factories, the `Clock`, MSW, two businesses in every tenant test.
4. **What isn't tested, and why** (honest gaps: real Google login, real Stripe, load).
5. **The bug hunt table.**

11. The bug hunt and `TESTING.md`.

## Test checklist

1. Fresh clone, Docker running, nothing else: `npm ci && npm run test:all` passes.
2. `npm test` passes **with Docker stopped**.
3. `npm run test:int -- --randomize` passes three times in a row.
4. Running one integration file alone (`npm run test:int -- bookings.repository`) passes.
5. The race test passes 10 times in a row (`-t "simultaneous"` in a loop).
6. Changing your computer's time zone (or `TZ=Asia/Dhaka`) doesn't change any result.
7. Turning off Wi-Fi doesn't change any result (MSW catches every outside call).
8. `npx playwright test --repeat-each=5 --workers=4` passes.
9. A PR that breaks a test can't be merged.
10. The bug hunt catches at least 11 of 12.
